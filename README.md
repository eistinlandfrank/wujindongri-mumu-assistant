# 无尽冬日 MuMu 助手 5.64.0

本版主程序为 `WJDRMuMuAssistant_v5.64.0_Portable.exe`，双击直接使用，无需安装 Python 或执行安装向导。首次启动会校验并解压到本机用户目录。需要 Windows 10/11 和已启用 ADB 的 MuMu 实例。

## 多手机使用

1. 先在 MuMu 中启动需要操作的手机，再打开助手。
2. 顶部“多手机窗口”列出在线设备；逐台打开独立窗口，或选择“打开其他所有手机”。打开窗口不自动启动游戏任务。
3. 在每个窗口选择自己的日常 / 巨兽任务并设置参数，再点击开始。标题栏标明设备，采矿和巨兽配置按账号保存；每个窗口只显示本机日志。
4. 运行中保持设备绑定，切换页面不会停止任务；停止按钮仅影响当前窗口，F8 统一急停。同一手机不允许重复工作线程。

2026-09-08 已核验两台真实 MuMu 的独立绑定、新截图与8页导航；四进程并发配置 / 体力记录测试通过。跨机器、不同游戏 UI 变体以及两账号长时间同时战斗，仍需单独验收，不能由双窗口连接成功推断全部兼容。

巨兽流程固定8级、3分钟、名称为“打野”的编组，一次一队。首次使用请先在游戏中保存“打野”阵容；未找到时会提示，不会默认选其他编组。绿色圆形图标＋同排“集结中”证明自建集结，蓝色为加入他人；绿色进度条不证明归属。全部部队回城后行军列表会消失，脚本在确认野外、侧栏收起且无列表证据的连续新帧中判断空闲，不再强求0/6。列表仍在但数字读不清时不会当作空闲。已确认出征后，野外页面可识别但队列短暂未知时只被动恢复，不重复发兵。

识别以1440×2560游戏内容为统一坐标参考，支持正常9:16截图的比例映射；不依赖桌面窗口大小。其他账号/机器仍需实测验收，不能保证所有UI变体已覆盖。200ms是本地识别与主动延迟的优化目标，不是游戏或ADB耗时承诺；本机最近PNG截图约0.54–0.75秒、原始像素约0.46秒。窗口直采虽更快，但验证未通过，尚未作为运行输入依据。

一个面向 MuMu Player 12 的 Windows 桌面工具。它通过 ADB 截图和模拟点击执行页面识别与联盟互助流程，不读取游戏内存、不修改 APK，也不读取账号密码。

4.48 保留训练数量减号的视觉定位：普通训练面板仍须同时出现左侧黄色“立即完成”、右侧蓝色训练和绿色滑条；减号只允许在屏幕最左侧 15% 的固定区域被识别。当绿色填充几乎消失时，必须额外以当前 MuMu 布局的精确“10”数值框在 0.985 阈值连续两帧匹配，防止把相似的“19”提前当作“10”。蓝色普通训练按钮只在已双帧确认的训练面板专属行内合并教程手势切开的蓝色控件碎片并取中心，排除下方兵营切换卡。训练启动后仅观察专用“训练中”文字；须先连续确认队列存在、再连续确认队列消失且普通训练面板恢复，才会返回兵营收取自然完成队列，绝不按固定时间猜测完成。任务前往后的转场会在同一窗口并行复核普通训练入口与盾兵完成教程；两者均须自身双帧稳定，先出现哪个仅走对应专用分支。自然采集返回后若每日任务入口已双帧可见，则直接重开每日任务；否则才使用已审核的世界地图回城路径。不会点击黄色“立即完成”、钻石或加速；每次每日流程最多执行 25 次双帧确认的绿色“全部帮助”。

## 主要能力

- 自动识别主城、联盟主页和联盟互助页面。
- 按“主城 / 世界地图 → 联盟 → 联盟互助 → 全部帮助”完成导航；只有确认联盟互助标题与绿色“全部帮助”按钮后才点击。
- 点击后重新截图确认；按钮消失时会丢弃旧坐标，避免持续盲点。
- 自动抢红包采用“红包浮标 → 聊天 → 联盟频道 → 熔炉升级红包 → 开启 → 结果页”逐步视觉确认；没有连续页面证据时不点击。
- “每日任务”自动化：领取连续两帧确认的任务奖励和已达标活跃度宝箱；可识别“采集生肉 / 木材 / 煤炭 / 铁矿”、三类训练、建筑升级、联盟捐献、英雄招募和仓库补给。仓库人物结果页即时关闭；情报仅走已审查路线。竞技场只从精确“进行1次竞技场挑战”及其同排“前往”进入，证明普通免费次数、我方战力与五名对手后连续清空当天免费次数，每场只选择战力严格低于我方的最低对手；不点刷新、加号或付费次数，回每日页后再领取1次和5次两档奖励。联盟捐献只允许双帧确认的蓝色普通食物，黄色钻石从不点击。每日活跃度 325 是最低目标：达标后停止一切新增进度路线，但会继续排空当前已完成奖励，最终分数可以超过 325。
- 独立冰原巨兽自动集结：固定8级，按账号保存体力上限（0表示不限），只允许野外搜索→冰原巨兽→精确3分钟→“打野”编组→普通出征；通过绿色图标与同排“集结中”确认自建归属，返回阶段不盲目忽略蓝色返回队伍。
- 支持 MuMu 多开：每个窗口固定绑定一个独立 ADB 设备；同一 Android 实例的不同 ADB 别名会合并并共用占用锁。
- 高 DPI 界面与跨分辨率模板缩放识别。

## 本地运行

日常修改先通过对应真实环境门禁，再展示前端并提交 GitHub，不必等 EXE 打包：

```powershell
powershell -NoProfile -File scripts/demo_frontend.ps1
```

它在 15 秒内确认窗口启动，不自动运行游戏任务，不停止已有任务。正式交付再生成完整免安装包；只有运行程序已编译且与当前源码一致时，才能使用 `packaging/build_portable.ps1 -SkipRuntime` 快速重新封装。源码演示不等于 EXE 启动验收。

需要 Windows 10/11、MuMu Player 12，以及已启用 ADB 的游戏实例。

```powershell
py -m pip install -r requirements.txt
py wjdr_mumu_assistant_qt.py
```

有人监看的命令行实机模式：

```powershell
py wjdr_mumu_assistant_qt.py --device 127.0.0.1:16448 --auto-daily
py wjdr_mumu_assistant_qt.py --device 127.0.0.1:16448 --auto-beast-rally
```

程序默认会扫描 MuMu 实例；也可通过界面选择目标实例。运行中的自动任务可用 `F8` 紧急停止。

要生成无安装便携版，请在 PowerShell 中运行：

```powershell
python scripts/run_bounded.py --seconds 295 powershell -NoProfile -ExecutionPolicy Bypass -File packaging/build_portable.ps1
```

默认输出为 `release_v5_63/WJDRMuMuAssistant_v5.63.0_Portable.exe`；运行目录位于 `release_v5_63/dist/WJDRMuMuAssistant`。公开发布前必须验证 Portable.exe 的真实解压与窗口启动路径，不得以 Setup.exe 代替。

## 项目文件

- `wjdr_mumu_assistant_qt.py`：当前 PySide6 桌面界面与任务编排。
- `wjdr_backend.py`：ADB、实例识别、截图匹配与点击逻辑。
- `alliance_*_builtin.png`：页面流程识别所需的内置模板。
- `assets/`：红包、每日任务与普通资源采集流程的内置识别模板。
- `build_release.ps1`、`version_info.txt`：Windows 便携版打包配置。
- `installer.iss`：仅在用户明确要求安装版时使用的可选配置，不是默认发行路径。

## 每日任务的安全范围

每日流程会先在任务页收取已完成任务奖励和已达标活跃度宝箱；主城默认打开“章节任务”时，只会在连续确认章节标题与未选中“每日任务”标签后切换一次。它还会在已验证的每日任务列表内限次上滑，识别训练、建筑、采集、联盟捐献、英雄招募、仓库补给和竞技场任务及同一卡片的“前往”。仓库结果只在该任务立即触发后的相关窗口内关闭；情报只走已审查路线。竞技场必须同时匹配1次任务标题与同排“前往”，进入后连续消耗可证明的普通免费次数至0，再回每日页领取1次和5次两档；对手战力、五英雄阵容、结算退出和次数恰减一都必须逐场复核。

采集路线仅允许“前往 → 世界资源搜索 → 资源类别 → 搜索 → 采集 → 出征”，每一步均需新截图连续确认。生肉任务由该任务自身的“前往”预选生肉，程序还会复核资源轮播中央“生肉”标签，绝不猜测或拖动资源轮播坐标。盾兵路线只允许“前往 → 兵营普通训练 → 双帧确认数量框 → 证明 Unity 编辑焦点 → 直接输入10 → 双帧复核10 → 蓝色训练 → 自然完成 → 兵营收取”。建筑路线只允许“已验证任务前往 → 建筑信息页 → 下方普通蓝色建造 → 自然完成”；若任务仍未完成，它只轮询等待，不会重复进入建筑。黄色立即完成、蓝色加速、钻石、钥匙、购买、战斗与非每日任务路由的升级均没有可执行坐标。联盟捐献任务仅允许蓝色普通食物按钮，必须见到联盟币计数变化才会进行下一次，容量耗尽立即停止。遇到未知页、付费礼包或遮挡层会停止且不做恢复点击。

## 注意

游戏服务条款可能禁止自动化、宏或机器人。请仅在自己承担风险的前提下进行短时、有人监看的测试，不要用于战斗、交易、充值或批量账号操作。
